# 战斗系统设计指南

本文档面向数值和机制设计师，说明战斗系统中需要配置的数据结构和设计要点。

---

## 1. 单位（BattleUnit）

每个战斗单位需要定义一份**数据模板**，包含六维基础属性和天生技能列表。

### 基础属性

| 字段 | 类型 | 说明 | 建议范围 |
|------|------|------|----------|
| HP | float | 生命值 | 100~2000 |
| Attack | float | 攻击力（技能伤害的基础参考值） | 10~200 |
| Defense | float | 防御力（K=1000, DEF=1000 时减伤约63%） | -500~2000 |
| Speed | float | 速度（影响行动频率，Speed 翻倍 = 行动频率翻倍） | 20~200 |
| Mana | float | 法力值（技能消耗的资源，当前未强制关联释放条件） | 50~500 |

### 防御力效果参考

防御力采用**比例减伤**模型，关键阈值：

| DEF | 减伤比例 | 说明 |
|-----|----------|------|
| 0 | 0% | 无减伤 |
| 100 | ~10% | 低防御 |
| 300 | ~26% | 中等防御 |
| 500 | ~39% | 高防御 |
| 1000 | ~63% | 极高防御 |
| 2000 | ~86% | 接近上限 |
| < 0 | 负值=增伤 | DEF=-1000 时受伤×2.5, DEF≤-2000 时受伤×5(上限) |

### 天生技能

每个单位至少配置一个技能（通常为普攻）。具备特殊定位的单位（如牧师、法师）可配置控制或持续伤害类技能。

---

## 2. 技能（Skill）

技能是单位在战斗中的行为单元。设计师需要为每个技能设定以下内容：

### 基础字段

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | string | 唯一标识，如 "fireball"、"heal" |
| DisplayName | string | 显示名称，如 "火球术"、"治愈" |
| SkillType | enum | 技能分类（影响技能表现和筛选） |
| TargetType | enum | 目标选择规则 |
| Level | int | 等级（影响函数通过闭包捕获此值实现数值缩放） |

### SkillType 可选值

| 值 | 含义 | 示例 |
|-----|------|------|
| SingleAttack | 单体攻击 | 普攻、重击 |
| Spread | 扩散攻击 | 溅射、连锁 |
| AoE | 范围攻击 | 暴风雪、地震 |
| Defense | 防御技能 | 护盾、铁壁 |
| Healing | 治疗技能 | 治愈、再生 |
| Support | 辅助技能 | 加速、加攻 |

### TargetType 可选值

| 值 | 含义     |
|-----|--------|
| SingleEnemy | 敌方单体单位 |
| AllEnemies | 敌方全体单位 |
| SingleAlly | 友方单体单位 |
| AllAllies | 友方全体单位 |
| SingleBoth | 双方单体单位 |
| AllBoth | 双方全体单位 |

## 3. 附加效果（BattleEffect）

附加效果是技能施加在单位上的持续性状态，包含 buff、debuff、持续伤害、控制等。

### 基础字段

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | string | 唯一标识，如 "poison"、"stun"、"atk_up" |
| DisplayName | string | 显示名称，如 "中毒"、"眩晕"、"攻击强化" |
| EffectType | enum | 正面(Positive) / 负面(Negative) / 其他(Other) |
| StatusType | enum | 控制(Control) / 属性变化(StatChange) / 持续伤害(Damage) / 标记(Mark) |
| InitialTurns | int | 初始持续回合数（每回合结束时 -1, 归零移除） |
| MaxStackCount | int | 最大叠加层数（同 ID+同来源时叠加并刷新回合） |

### 叠加规则

相同的效果（Id 相同 + 施加来源相同）会叠加：
- 层数 +1（不超过 MaxStackCount）
- 剩余回合重置为 InitialTurns

不同来源施加的同 Id 效果视为独立实例。

### StatusType 与结算时机

| StatusType | 结算时机 | 说明 |
|------------|----------|------|
| Damage | 仅 PreAction | 持续伤害，每个行动回合开始时结算一次 |
| Control | 效果施加时 + 每次属性刷新 | 设置 CanAct = false 等 |
| StatChange | 效果施加时 + 每次属性刷新 | 修改攻击/防御/速度等乘数或额外值 |
| Mark | 效果施加时 + 每次属性刷新 | 标记类效果（用于其他技能的触发条件判断） |

属性刷新时机：每个技能释放后（全体单位）、PostAction 结束时（自身）、PreAction 开始时（自身）。

## 4. 设计流程建议

### 第一步：确定单位数值

1. 设定 HP、Attack、Defense、Speed、Mana 的基础值
2. 使用伤害公式验证：`最终伤害 = 原始伤害 × (1-DamageReduction) × (1-DefenseRate) - Shield`
3. 使用行动值公式估算行动频率：`ActionValue = RemainingCost / Speed`

### 第二步：设计技能

1. 确定技能类型（攻击/治疗/辅助）
2. 确定目标类型（单体/全体/友方/敌方）
3. 填写伤害/治疗/法力消耗的数值
4. 如需条件限制，添加 CanCastConditions

### 第三步：设计附加效果

1. 确定效果类型和状态类型
2. 设定持续回合（考虑叠加上限 = MaxStackCount × InitialTurns）
3. 设定属性修正的乘数和额外值（注意 ResetModifiers 会在效果刷新时重置所有乘数为 1.0）
4. 控制类效果注意：属性刷新后 CanAct 会被重新设置为 false（由效果函数保证）
